## 2. What you build

Server paths are under `backend/monolith/`.

**The sign-out contract** (`apps/accounts/views.py` `SignOutView` and `_proven_sign_in`;
`apps/accounts/sessions.py` `end_session`). `POST /api/auth/sign-out` with a refresh token in the
body and no bearer needed:

- **205** when the token's signature verifies as ours, whatever else is true of it: its sign-in
  is live, already ended, expired, rotated, or belongs to an account that no longer exists. After
  a 205 the sign-in is ended and every push device it registered is off. A repeat answers 205 and
  writes nothing.
- **400 with code `sign_out_proof_invalid`** when the token cannot be verified as ours, or is
  missing. This replaces today's 401.
- A valid access token may stay accepted as proof, as today. The body's installation id and
  sequence are no longer read.

**N-B. The sign-in row decides** (`sessions.py`; `apps/notifications/push.py`).

- `end_session` writes nothing when the sign-in is not live.
- A sign-out records nothing in the installation's order. `deactivate_session_push_devices` only
  switches off the devices of that sign-in. Remove the sign-out operation from
  `PushInstallationBinding` if nothing else writes it.
- No operation writes the installation's order before it has checked, under the account lock,
  that its sign-in is live. Registration already does; make unregister the same.

**N-D. Credentials and privileges have named writers.** No override of `User.save()`.

- **One credential writer.** One function sets a password and ends every sign-in of the account,
  under the account lock. Every `set_password` on an existing account goes through it: the reset
  in `apps/accounts/views.py`, `apps/accounts/serializers.py`, `apps/admin_panel/services.py`,
  the bootstrap command, and the technical admin's password form.
- `session_epoch` keeps one writer, `end_all_sessions`.
- **Every save of an existing user row names its fields.** Convert the inventory:
  `apps/admin_panel/services.py`, `apps/accounts/social.py`, `apps/accounts/deletion.py`,
  `apps/accounts/serializers.py`, the bootstrap command, and any other you find.
- **The technical admin saves only what the form changed** (`apps/accounts/admin.py`,
  `ShipTripUserAdmin.save_model`): for an existing user, `obj.save(update_fields=...)` with the
  model fields in `form.changed_data`. The password and `session_epoch` are never among them.
- **Staff rights are read only in the technical admin** (decision D5): the staff and superuser
  flags, groups, permissions and "active" join `readonly_fields`, with one line that says where
  to change them, as `ban_state` does for the ban. **[Guess]** The console has an audited action
  for each (`change_admin_role`, `set_admin_access`, the invitation flow, the bootstrap command
  for the first superuser, account deletion for "active"). List the action for each field in the
  pull request. A field with no action stays editable, and you tell the lead. If the lead says D5
  was refused, skip this item.

**N-F. A push belongs to the sign-in that registered the device** (`push.py`
`enqueue_fcm_for_event`; `backend/services/internal/notification/fcm_devices.go` and the retry
path).

- A queued push carries, for each device, the sign-in that registered it.
- The worker's last check before sending (`stillBoundQuery`) compares user, device, token
  fingerprint and that sign-in with the row as it is now. A device rebound to another sign-in, of
  the same member or another, does not receive it. A retry checks again.
- The socket-expiry fix of round 4 stays, with its test.

**The phone.** Change nothing in how the phone exits a sign-in, except what its tests need to
stay true with the new sign-out answers. Make no exit worse than on `main`.

## 5. Tests

Red first: round-5 blocker 1 (the technical admin's full-row save writes back the old password
hash and `session_epoch` after a reset) and the should-fix (a repeated sign-out of an ended
sign-in advances the installation's order).

- **Sign-out contract:** a live proof; an expired proof; a rotated proof; a proof of a deleted
  account; an unverifiable proof; no proof. A repeat after a 205 makes zero writes.
- **N-B:** a sign-out for a sign-in a password reset already ended; A's delayed sign-out after B
  registered on the same installation; A's registration arriving after A's sign-out; one account
  with two sign-ins on one installation; an unregister against a newer register.
- **N-D:** the technical admin form read on POST, then a reset, then the save: the new password
  and `session_epoch` hold, checked with a real sign-in and a real refresh. Each converted save
  with a concurrent change of another field. A POST that tries to submit a read-only staff right
  changes nothing.
- **N-F:** a queued send and a queued retry across a rebind to another member, and to a new
  sign-in of the same member with the same token.

Mechanical checks: a scan test that fails on a save of a loaded user without `update_fields`,
and on `password` or `session_epoch` named anywhere but in their writers.
