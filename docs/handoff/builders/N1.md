## 4. What you build

Server paths are under `backend/monolith/`.

**The sign-out contract** (`apps/accounts/views.py` `SignOutView` and `_proven_sign_in`;
`apps/accounts/sessions.py` `end_session`). `POST /api/auth/sign-out` with a refresh token in the
body and no bearer needed:

- **205** when the token's signature verifies as ours, whatever else is true of it: its sign-in is
  live, already ended, expired, rotated, or belongs to an account that no longer exists. After a
  205 the sign-in is ended and every push device it registered is off. A repeat answers 205 and
  writes nothing.
- **400 with code `sign_out_proof_invalid`** when the token cannot be verified as ours, or is
  missing. This replaces today's 401.
- A valid access token may stay accepted as proof, as today. The body's installation id and
  sequence are no longer read.

**N-B. The sign-in row decides** (`sessions.py`; `apps/notifications/push.py`).

- `end_session` writes nothing when the sign-in is not live.
- A sign-out records nothing in the installation's order. `deactivate_session_push_devices` only
  switches off the devices of that sign-in. Remove the sign-out operation from
  `PushInstallationBinding` if nothing else writes it.
- No operation writes the installation's order before it has checked, under the account lock,
  that its sign-in is live. Registration already does; make unregister the same.
- Register and unregister keep their ordering among live sign-ins, and an exact repeat is
  recognised by operation, account, sign-in and token together.

**N-D. Credentials and privileges have named writers.** No change to how the model saves in
general: no override of `User.save()`.

- One credential writer: one function sets a password and ends every sign-in of the account, under
  the account lock. Every `set_password` on an existing account goes through it: the reset in
  `apps/accounts/views.py`, `apps/admin_panel/services.py`, the bootstrap command, and the
  technical admin's password form.
- `session_epoch` keeps one writer, `end_all_sessions`.
- Every save of an existing user row names its fields. Convert the inventory:
  `apps/accounts/admin.py`, `apps/admin_panel/services.py`, `apps/accounts/social.py`,
  `apps/accounts/deletion.py`, `apps/accounts/serializers.py`, the bootstrap command, and any other
  you find.
- A form that can submit a sensitive field carries what the staff member saw. Sensitive fields:
  the staff and superuser flags, groups and permissions, active, banned, role, and the
  verification flags. The technical admin form (`ShipTripUserAdmin`) and the console's staff
  actions send the values shown when the page opened. Under the account lock, a difference
  between those and the row rejects the edit with "this account changed since you opened it". A
  second removal of the same privilege reports that it was already done.

**N-F. A push belongs to the sign-in that registered the device** (`push.py`
`enqueue_fcm_for_event`; `backend/services/internal/notification/fcm_devices.go` and the retry
path).

- A queued push carries, for each device, the sign-in that registered it.
- The worker's last check before sending (`stillBoundQuery`) compares user, device, token
  fingerprint and that sign-in with the row as it is now. A device rebound to another sign-in, of
  the same member or another, does not receive it. A retry checks again.
- The socket-expiry fix of round 4 stays, with its test.
- Not yours: a push already handed to Google or Apple (decision D8, its own package), and clearing
  shown notifications (S1).

**The phone.** Change nothing in how the phone exits a sign-in, except what its tests need to stay
true with the new sign-out answers. Make no exit worse than on `main`.

## 7. Tests

Red first: round-5 blocker 1 (the technical admin's full-row save writes back the old password
hash and `session_epoch` after a reset) and the should-fix (a repeated sign-out of an ended
sign-in advances the installation's order).

- **Sign-out contract:** a live proof; an expired proof; a rotated proof; a proof of a deleted
  account; an unverifiable proof; no proof. A repeat after a 205 makes zero writes.
- **N-B:** a sign-out for a sign-in a password reset already ended; a reset before the first
  registration; A's delayed sign-out after B registered on the same installation; A's registration
  arriving after A's sign-out; one account with two sign-ins on one installation; low, equal and
  highest sequences among live operations; an unregister against a newer register; a lost
  acknowledgment.
- **N-D:** the technical admin form opened, a privilege removed elsewhere, then the old form
  posted to change a name; the form read on POST, then a reset, then the save; two removals of one
  privilege; every converted save with a concurrent change of another field; deferred and reloaded
  instances. After each, the new password and `session_epoch` hold, checked with a real sign-in
  and a real refresh.
- **N-F:** a queued send and a queued retry across a rebind to another member, and to a new
  sign-in of the same member with the same token (Go tests, with the integration test); socket
  expiry.

Mechanical checks: a scan test that fails on a save of a loaded user without `update_fields`, and
on `password` or `session_epoch` named anywhere but in their writers; a test that no
installation-order write happens before the liveness check.

Run the Go checks too: `gofmt`, `go build`, `go vet`, `go test -race`.

## Rules, the same for every builder

1. Build what this brief names and nothing else. Add no lock, counter, generation, flag, column,
   job kind or retry loop that the plan does not name. If one seems needed, stop and ask.
2. Red first. Reproduce each finding listed under "Tests" as a failing test before you fix it. A
   failing test must tell the bad outcome apart from a correct serial execution.
3. Group tests by family, in files named after the invariant. Never skip, delete or weaken a test.
   A test of a mechanism you delete is rewritten to the new rule, and the pull request lists it
   with the reason.
4. Remove what you replace in the same pull request. The tests of the closed families stay green.
5. The server enforces every rule. The app never fakes a result. Every user-facing string exists
   in English, French and Arabic.
6. After a migration, run `task check-drift` in `backend/` and commit the regenerated contract.
7. Push only to your branch, with ordinary pushes: no force push, no rebase of pushed commits. The
   whole suites and the Android build run in GitHub CI on the branch. While you fix, re-run locally
   only the tests that failed. The work is ready only when every CI check is green, "Schema drift"
   included.
8. Never deploy, never restart or change a server, never build the app for a device. The
   repository is public: no server address, account email, key, token or password in a file, a
   commit, the pull request or a comment.
9. Do not edit `HANDOFF.md`, the plan, or files that belong to another brief. Do not merge. Write
   nothing on GitHub except the pull request description.
10. No model name in a commit, a pull request or a document. Do not use the word "partner".
