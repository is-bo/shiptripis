## 1. Your job

The money code still tells "legacy" rows apart from current ones: deals agreed under the old DZD
contract, payments and payouts that were never marked test or live, payout instructions from
before the current model. No such row exists, and none can be created. Remove the markers, the
branches and the report surfaces that exist only for them. No money result for current data may
change, and no number on a finance page may change for current data.

## 3. How

1. **Inventory first**, as plan section 3.5 says.
2. **Show that no legacy row can be created.** For each marker: every write path stores a
   current value (test or live; the current economics version; not legacy), shown by reading the
   paths and by a test. Where a constraint can say it, the constraint says it.
3. **Differential test for the finance pages.** Before you remove a cohort or a branch from a
   report, a test builds current-data fixtures (payments, refunds, payouts, ledger entries, in
   test and in live mode) and compares the full output of each finance page, each export and
   each control-plane query before and after. It passes at every commit and is deleted in the
   last one, with any frozen copy.
4. Remove the branches, then the columns and enum values, each in a migration of its own app.
5. `payout_release` and `evaluate_payout_release` decide whether money leaves. Remove only the
   legacy branch. For every current case the decision and its reason code are the same.

## 4. What is not yours

The dead apps (L1). Schema versions (L2). Any change to a money, fee, refund or payout result
for current data: if you find one, stop and ask. The layout of the finance pages beyond removing
the legacy cohort, its filter and its labels.

## 5. Proof

- The differential test, green at every commit until its removal.
- The existing tests of payout release, checkout, refund and ledger pass unchanged. Each removed
  or rewritten test is listed with its reason.
- `backend/contracts/sql/schema.sql` changes only by the listed columns, values and constraints.
- Each removed payload field or code (`is_legacy`, `legacy_contract_not_supported`) is searched
  in `mobile/lib`. What the app still names goes on the list for brief MC.
- Screenshots of the finance pages whose filters or labels changed.
