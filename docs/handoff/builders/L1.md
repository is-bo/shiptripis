## 3. How

1. **Inventory first.** For each item: the search that shows no live code reads or writes it
   (code, tests, fixtures, templates, settings, strings, `apps.get_model` and other dynamic
   references). An item with a live reader is not dead, whatever its name: leave it and list it.
2. **Chat eligibility is a rule.** Before you delete the old branch, show that it can be reached
   only by a row of the old kind, and that no current write path creates such a row. If a current
   row can reach it, stop and ask.
3. Delete the code. In each dead app, one migration deletes its models. The app keeps an empty
   shell (`__init__.py`, `apps.py`, `migrations/`) because older migrations of other apps name
   it. Nothing else of the app stays.
4. Foreign keys from live models to a dead model are removed in the live app's own migration,
   before the dead model goes.

## 4. What is not yours

The old `Trip`, `ProductRequest` and the schema versions (L2). The legacy money markers in
`apps/finance`, deals and boosts (L3). Other compatibility code (L4). No behaviour change of any
kind: if a deletion would change an answer, stop and ask.
