**Checked and found sound.** I reviewed origin/main...227d8aa31f2cfdd60ad928c1fa50d71a862bf5b2 from merge base d0dc800. Registration, sign-out, unregister and end-all take the account lock before device mutation, with the installation binding locked before devices wherever both are used. Once a sign-in row has ended, its rotated refresh is refused and its access token cannot register a phone. I found no production user-token issuer bypassing _tokens_for_user. The exact-repeat identity includes the sign-in, and an acknowledged repeat preserves the device. Requiring binding_sequence on registration and deleting pre-session devices are consistent with CLAUDE.md. Offline sign-out is accurately documented as best-effort.

On the phone, the first-open checks cover first paint, Firebase readiness, foreground state, splash, auth-route transitions, guest payment and a pending notification destination. The Profile action rechecks its route after the count write. The pinned Android plugin supports the fresh-install and denial mappings used here and makes no runtime request below API 33. The iOS undetermined, provisional and authorized paths, guest grant followed by sign-in, bounded 409 retry, and retry after a failed catch-up write are covered in source and tests. Both HTTP 500 retry tests retain behavioral assertions. The two new storage values are integers, the handover test retains its exact key allowlist, and the changed strings exist in EN, FR and MSA with "Wassla" in Latin script.
