{% comment %} The page a guest payer lands on from a shared link. Everything about it is shaped by one constraint: the person reading it is not a ShipTrip user and must not become one by opening it. So the page shows an amount, what kind of payment it is in the most generic terms the system can state, and how long the link lasts -- and nothing else. No sender, no traveler, no recipient, no addresses, no parcel, no deal, no order reference. A payer who forwards this link forwards the ability to pay, not a receipt and not a record. The token is in the URL because it *is* the credential. The page never puts it in a query string, never logs it, and the server stores only its hash. The referrer is suppressed so the path never travels onward to anyone. An invalid, expired, revoked or already-paid link is answered the same way, in the same words: the link no longer works. Distinguishing them would let someone holding a guessed token learn which orders exist. Visually it is the app, not a web interpretation of it: parchment, ink, terracotta, Fraunces for the one figure the page is about, DM Sans for the rest, the wax seal as the mark. The values are `AppColorScheme` verbatim, and the faces are the landing site's own subsets under /assets/fonts. No script, no external request, no gradient. {% endcomment %} {{ t.title }}
