{% extends "payments/_shell.html" %}{% comment %} The page a guest payer lands on from a shared link. Everything about it is shaped by one constraint: the person reading it is not a ShipTrip user and must not become one by opening it. So the page shows an amount, what kind of payment it is in the most generic terms the system can state, and how long the link lasts -- and nothing else. No sender, no traveler, no recipient, no addresses, no parcel, no deal, no order reference. A payer who forwards this link forwards the ability to pay, not a receipt and not a record. The token is in the URL because it *is* the credential. The page never puts it in a query string, never logs it, and the server stores only its hash. The referrer is suppressed so the path never travels onward to anyone. An unknown, expired, revoked or closed link is answered the same way, in the same words: the link is no longer active. Distinguishing them would let someone holding a guessed token learn which orders exist. The one exception (J7D) is a real link whose payment is complete: its holder -- the person who just paid, opening the link again -- is told so instead of being sent back to ask for a new link. Only a token that hashes to a stored link reaches that branch, and a token cannot be guessed, so it tells a prober nothing. Its look -- tokens, faces, header and language switch -- is the shared `payments/_shell.html`, which the provider-return page uses too (J7D). {% endcomment %} {% block content %}
